模块以一组独立可执行的 Python 脚本组织，按职责划分为四类：
- 源码同步与重基线：`trunk.py`、`tot.py` 通过 `gclient sync`、`git rebase-update` 将 Chromium 仓库切换到指定分支或 tip-of-tree，并清理 v8/devtools/ffmpeg 等子模块。
- 环境准备与补丁应用：`setup.py` 是主入口，负责把 Thor/MCloud 源码目录（由 `THOR_DIR` 指定）拷贝到 Chromium 树（`CR_DIR`），复制 `mcloud-libjxl`、`src/*`、`pak` 二进制，并将 `other/*.patch` 逐一 `git apply --reject`；同时根据 `--woa` / `--avx512` / `--avx2` 参数切换 ARM64、AVX-512、AVX2+FMA3 三种目标架构的 third_party 覆盖与 PGO profile 下载。
- 定点增量部署：`deploy_mcloud.py` 作为统一编排器，顺序调用 `copy_essentials.py` → `apply_polly_wiring.py` → `append_polly_configs.py` → `apply_avx2_baseline.py` → `apply_mcloud_source_defaults.py` → `inject_flags_loader.py`，最后复制 `mcloud_flags.txt` 到 `out/mcloud`，供后续 `gn gen out/mcloud --check` 使用。
- 构建与工具：`build_win.py` 调用 `autoninja -C out/mcloud mcloud_all && setup mini_installer` 完成最终产物生成；`version.py`、`upstream_version.py`、`reset_depot_tools.py`、`verify_sources.py` 为辅助工具。
依赖方向单向：`deploy_mcloud.py` 编排其他脚本，`setup.py` 依赖 `other/*.patch` 与 `mcloud-libjxl`，所有脚本均通过 `CR_DIR`/`THOR_DIR` 环境变量与外部 Chromium 树交互，不直接修改彼此。
